선생님을 위한 바이브 코딩 가목차

선생님들이 엑셀에 적어 주신 웹앱 아이디어와, 가목차

작성 날짜: 2026년 10월 7일

목차 아이디어 최종 목차 기획자 의견 작업 이력

참고: 기존 도서 샘플 목차와 다룬 앱

기획자 의견 ─ 가목차 보는 방법

※ 기획자 = 조아리 팀장

✅ 선생님들께서 협의 후 전달해 주실 것

  • 목차별 담당 선생님 (1·2권 모두)
  • 조정하고 싶은 목차가 있다면 그 의견
  • [2권] 가안 목차를 쓰기 어려운 경우, 파트별 대체 목차

→ 선생님들끼리 협의해 정리한 뒤 기획자에게 전달해 주세요.

공통1·2권 공통 사항

사용 도구 · 라벨 표기

  • 1·2권 모두 챗GPT의 Codex를 활용합니다.
  • 라벨의 ‘챗GPT’는 Codex를 뜻합니다.
    (Codex라는 용어가 낯설 수 있어 ‘챗GPT’로 표기했습니다.)

PART 1 작성 방식

  • 선생님마다 한 꼭지씩 맡아 작성합니다.
  • 1·2권 PART 1에는 공통으로 들어갈 내용이 있어, 편집자가 두 권의 원고를 검토한 뒤 합쳐서 편집할 예정입니다.

원고 담당 배분

  • 아이디어별 원고 담당은 선생님들끼리 협의해 정해 주세요.
  • 정해진 담당자를 목차별로 정리해 기획자에게 전달해 주세요.

목차 조정

  • 조정하고 싶은 목차가 있으면 선생님들끼리 협의해 의견을 정리해 주세요.
  • 전달해 주시면 반영하겠습니다.

부록

  • 전체 내용을 구성한 뒤, 빌드·배포에 필요한 내용을 기획자가 정리해 전달드립니다.
  • 이를 바탕으로 원고를 작성해 주시면, 1·2권 공통 부록으로 정리해 편집합니다.

1권수업자동화

라벨 보는 법

  • 제목 앞 라벨 : 선생님께서 의견 주신 과목
  • 제목 뒤 라벨 : 확장 가능한 과목

파트별 분량 · 난이도

  • PART 1·2 : 아주 간단하게
    • 약 300쪽 안에 담을 프로그램이 많습니다.
    • 어렵고 자세하게보다는, 쉽고 간단하게 바이브 코딩을 재설계해 작성해 주세요.
  • PART 4 (심화) : 분량을 좀 더 늘려도 괜찮습니다.

참고

  • PART 4는 업무자동화 저자 선생님께서 주신 아이디어입니다. 참고로 봐 주세요.

2권업무자동화

구성 원칙 : DB 활용

  • DB를 활용하는 내용을 포함합니다.
  • DB를 활용하는 목차는 각 파트의 뒤쪽에 배치합니다.

분량 · 난이도

  • 약 300쪽에 프로그램 30개를 담아야 합니다.
    • 1권과 마찬가지로, 자세하게보다는 쉽고 간단하게 재설계해 작성해 주세요.
    • DB를 활용하는 원고는 분량을 조금 더 써도 좋습니다.

가안 목차 안내

  • 2권은 목차가 부족해 보여 기획자가 가안 목차를 제시했습니다.
  • 가안을 쓰기 어려우면, 파트별로 목차를 정리해 기획자에게 전달해 주세요.

AI 활용이 불가능한 항목 작성 요령

  • 생기부·세특은 ‘AI 활용 문장 사용 불가’ 지침에 따라, 문장 생성 대신 다른 기능을 활용하도록 구성했습니다.
  • 이처럼 AI를 활용할 수 없는 내용이 있다면, 원고에 “지침상 AI를 활용할 수 없어 이런 기능을 대신 만들어 봤다”는 설명을 남겨 주세요.

가목차 페이지를 고치고 더한 내역입니다. 최근 작업이 위에 있습니다.

가목차 초안입니다. Part 2부터 실습 꼭지를 권마다 30개로 맞췄고, 아이디어가 없는 자리는 가안(저자 미정)으로 채웠습니다. 난이도 및 내용 검토가 필요하다고 판단한 챕터는 각 권 아래 ‘재검토 아이디어’에 정리했습니다.

엑셀 ‘최종목차’ 탭에 확정한 목차입니다. 꼭지마다 바탕이 된 아이디어를 연결해 두었고, 아이디어를 누르면 해당 카드로 이동합니다.
