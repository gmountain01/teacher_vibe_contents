# 학교 파일 제출 웹앱 설치 안내

이 자료는 하나의 Apps Script 프로젝트에서 공개용·교직원용 배포를 만드는 전체 소스입니다. 실제 계정 연결·배포·메일 발송은 수행하지 않았습니다. 요청에 따라 브라우저 실행·화면 캡처·테스트도 수행하지 않았습니다. 학교 운영에 적용하기 전 학교 담당자가 계정 정책과 자료 보관 기준을 확인해야 합니다.

## 1. 준비할 것

- 학교 Google Workspace 계정. 프로그램을 소유하고 운영할 관리자 계정을 사용하세요.
- 학교 조직에서 Apps Script, Drive, 외부 익명 웹앱 접속을 허용해야 합니다.
- 학생 명렬표와 파일을 보관할 충분한 드라이브 공간.
- 같은 조직에서 웹앱 접속자의 이메일을 확인할 수 있는 환경.

다른 조직 계정이나 개인 Gmail을 관리자 계정으로 사용하도록 만든 소스가 아닙니다. 관리자가 자신의 학교 계정으로 로그인해서 만들면 설정이 간단해집니다. 구글 계정 비밀번호를 이 프로그램에 입력하는 일은 없습니다.

## 2. 새 프로젝트 만들기

1. 학교 관리자 계정으로 https://script.google.com/ 에 접속합니다.
2. `새 프로젝트`를 누릅니다.
3. 위쪽 프로젝트 제목을 `학교 파일 제출`로 바꿉니다.
4. 기본 `Code.gs`의 예제 코드는 삭제합니다. 이 파일을 `설정`으로 이름 변경해도 됩니다.
5. 왼쪽 파일 옆 `+`에서 스크립트를 추가하여 아래 파일들을 만듭니다. `.gs` 확장자는 편집기가 붙이므로 파일 이름만 입력합니다.

| 편집기 파일 | 붙여 넣을 원본 | 역할 |
|---|---|---|
| 설정.gs | 설정.gs 전체 | 초기화·시트·권한·공통 기능 |
| 서버.gs | 서버.gs 전체 | 화면 진입·학부모 업로드·조회 |
| 관리.gs | 관리.gs 전체 | 관리자·교사·파일 관리 |
| 화면.html | 화면.html 전체 | 모든 사용자 화면 |
| appsscript.json | appsscript.json 전체 | 시간대·필요 권한 |

`화면`은 `+ → HTML`로 추가합니다. 이름이 정확히 `화면`이어야 합니다. 여러 파일이 같은 프로젝트 안에 있어야 합니다. 각 스크립트는 독립 프로젝트로 만들지 마세요.

## 3. 관리자 이메일 두 곳 바꾸기

`설정.gs` 맨 위의 다음 값을 실제 값으로 수정합니다.

```
관리자이메일: 'admin@school.example.kr',
학교도메인: 'school.example.kr'
```

예를 들어 학교 계정이 `teacher@abc-school.kr`이면 관리자이메일에 `teacher@abc-school.kr`, 학교도메인에 `abc-school.kr`을 입력합니다. 따옴표와 쉼표를 유지하세요. 예시 값 그대로 실행하면 중단됩니다.

여기서 관리자는 교사 인증 신청을 할 필요가 없습니다. 다만 해당 Google 계정으로 로그인해야 합니다.

## 4. 설정 파일 표시하기

1. 왼쪽 톱니바퀴 `프로젝트 설정`을 누릅니다.
2. `편집기에 appsscript.json 매니페스트 파일 표시`를 켭니다.
3. 편집기로 돌아와 `appsscript.json`을 엽니다.
4. 제공된 `appsscript.json` 전체 내용으로 바꾸고 저장합니다.

외부 라이브러리 설치나 별도 API 키 발급은 필요하지 않습니다. 본 소스의 ZIP·다운로드는 내장 서비스만 사용합니다. 화면용 SUIT 무료 폰트만 외부 CDN에서 읽고, 실패하면 시스템 글꼴을 사용합니다.

## 5. 최초 초기화

1. 편집기 위쪽 함수 선택 메뉴에서 `초기설정`을 고릅니다.
2. `실행`을 누릅니다.
3. 권한 검토가 표시되면 현재 학교 관리자 계정을 선택합니다.
4. 요청하는 시트·드라이브·트리거 권한을 확인하여 허용합니다.
5. 실행 로그의 `초기화 완료`를 확인합니다.

학교 정책에서 권한 승인이 막히면 학교 Workspace 관리자에게 문의하세요. 보안 차단을 임의로 우회하지 마세요.

자동 생성되는 자료:

- `학교 파일 제출 DB` 스프레드시트와 13개 데이터 시트.
- `학교 제출자료` 드라이브 폴더.
- `_임시파일` 폴더.
- 하루 한 번 실행되는 `정기정리` 트리거.
- 데이터 ID, 학교 도메인, 관리자 계정, 서버 비밀값 등 Script Properties.

실행 로그에 시트와 폴더 주소가 나옵니다. 다시 실행해도 기존 자료를 지우지 않습니다. 초기화는 익명 방문 시 자동 실행되지 않습니다. 반드시 운영자가 편집기에서 한 번 실행하세요.

## 6. 첫 번째 배포: 학부모 공개용

1. 오른쪽 위 `배포 → 새 배포`를 누릅니다.
2. 유형 선택에서 `웹 앱`을 선택합니다.
3. 설명에 `학부모 공개용`을 입력합니다.
4. 실행 사용자는 `나`로 선택합니다.
5. 접근 권한은 익명 접속을 허용하는 `모든 사용자` 항목을 선택합니다. 계정 정책에 따라 선택지 이름이나 제공 여부가 다를 수 있습니다.
6. 배포하고 `/exec`로 끝나는 웹앱 URL을 복사합니다.

이 주소를 A라고 부릅니다. 학부모에게 안내할 주소입니다. `/dev` 주소는 운영용이 아닙니다.

학교 정책상 익명 배포를 선택할 수 없다면 요구한 익명 업로드는 그대로 사용할 수 없습니다. 접근 설정을 허용받거나 로그인 방식으로 요구사항을 조정해야 합니다.

## 7. 두 번째 배포: 교직원용

1. 같은 프로젝트에서 다시 `배포 → 새 배포 → 웹 앱`을 선택합니다.
2. 설명에 `교직원 제한용`을 입력합니다.
3. 실행 사용자는 역시 `나`로 선택합니다.
4. 접근 권한은 학교 조직 사용자만 접근할 수 있는 항목을 선택합니다.
5. 배포하고 `/exec` 주소를 복사합니다.

이 주소를 B라고 부릅니다. A와 B는 서로 다른 배포 주소입니다. B에 개인 Gmail 접근을 허용하지 마세요.

이 구성은 학교 조직 환경에서 접속자 이메일을 확인할 수 있다는 조건을 사용합니다. 이메일을 얻지 못하면 관리자나 교사를 추측하지 않고 차단합니다. `getEffectiveUser()`는 방문자 확인에 쓰지 않습니다.

## 8. 두 주소 등록: 처음 한 번만

아직 주소 설정을 하지 않았으므로 처음에는 다음 주소를 직접 만듭니다.

```
B?page=admin&entry=1
```

위 B를 실제 두 번째 배포 주소로 바꾸세요. 예를 들어 B가 `https://script.google.com/macros/s/배포ID/exec`이면 그 뒤에 `?page=admin&entry=1`을 붙입니다.

1. 초기화에 사용한 관리자 학교 계정으로 이 주소에 접속합니다.
2. Google 로그인 화면이 나오면 해당 계정으로 로그인합니다.
3. 관리자 화면의 `운영 설정`을 누릅니다.
4. 공개 배포 주소에 A를 넣습니다.
5. 교직원 배포 주소에 B를 넣습니다.
6. 주소에는 `?page=...`를 붙이지 않고 `/exec`까지 입력합니다.
7. 저장합니다.

그다음부터는 A 뒤에 `?page=admin` 또는 `?page=teacher`를 붙여 안내 화면부터 접속합니다. 관리자 계정임에도 접근되지 않으면 현재 Google 계정·학교 도메인·Script Properties의 ADMINS를 확인하세요.

## 9. 사용 주소 정리

| 사용자 | 접속 주소 | 동작 |
|---|---|---|
| 학부모 | A | 학생 입력부터 시작 |
| 학부모 명시 주소 | A?page=parent | 동일한 학부모 화면 |
| 관리자 | A?page=admin | 로그인 안내 → 버튼 → B의 관리자 페이지 |
| 교사 | A?page=teacher | 로그인 안내 → 버튼 → B의 교사 페이지 |

안내 버튼은 B의 같은 역할 페이지와 `entry=1`로 이동합니다. `entry`는 화면 안내 단계를 구분할 뿐 인증이나 권한을 부여하는 값이 아닙니다. 실제 권한은 모든 서버 작업에서 다시 확인합니다.

Google 로그인 페이지는 배포 접근 제한이 표시합니다. 앱에 Google 로그인 화면을 복제하거나 삽입하지 않습니다. B를 직접 열면 앱의 안내 화면보다 Google 로그인이 먼저 나올 수 있습니다. 계정 선택 화면이 자동으로 다시 표시되지 않을 때는 Google 계정 메뉴에서 학교 계정을 선택하거나 별도 브라우저 프로필을 사용하세요.

## 10. 운영자가 처음 입력할 순서

1. `제출함 관리`에서 학년과 시작·마지막 반을 입력하여 학급 제출함을 만듭니다. 학년별로 반복합니다.
2. 같은 화면에서 필요한 일반 제출함을 만듭니다. 예: 공개수업 신청, 체험학습 자료.
3. `학생 명렬표`에서 CSV 양식을 내려받습니다. 예시 학생 행을 실제 명렬표로 바꿔 저장합니다.
4. CSV를 올리고 `내용 확인 → 반영`을 누릅니다. 등록 전에 해당 학급이 있어야 합니다.
5. `교사·권한`에서 교사를 등록하거나 신청을 승인합니다.
6. 담임을 배정합니다. 담임은 해당 학급 열람·다운로드 권한을 받습니다.
7. 일반 제출함도 담당 교사를 선택하고 권한을 저장합니다.
8. 학부모에게 A 주소를 안내합니다.

담임 신청을 승인하기 전에 해당 학년도·학급 제출함을 먼저 만드세요. 학급 범위를 줄였다는 이유로 기존 제출함은 삭제되지 않습니다. 필요 없는 제출함은 관리자가 비활성화합니다.

## 11. 교사 이용

- A?page=teacher에서 로그인 버튼을 누릅니다.
- 미등록 계정이면 인증 신청 화면이 표시됩니다.
- 이름·로그인한 학교 이메일·담임 여부를 입력합니다.
- 관리자가 승인하면 `승인 상태 확인`을 누릅니다.
- 권한이 있는 학년도와 제출함을 선택해 목록·다운로드를 사용합니다.
- 이름 변경·이동·삭제는 파일 관리 권한이 있어야 처리됩니다. 버튼이 보여도 권한이 없으면 서버에서 거절합니다.

같은 이름의 교사는 이메일과 내부 ID로 구분합니다. 교사를 삭제하거나 중지해도 학생 자료는 보존합니다. 권한을 모두 해제하고 저장하면 해당 교사의 제출함 접근을 회수합니다.

## 12. 학부모 이용

1. 학생·보호자 정보와 임시암호를 입력합니다.
2. 동명이인이면 학생 번호를 추가 입력합니다.
3. 제출함을 고르고 파일을 여러 개 선택합니다.
4. `전송`을 누르고 완료까지 기다립니다.
5. 일부 실패하면 같은 화면에서 전송을 다시 누릅니다. 저장된 파일은 재전송하지 않습니다.
6. 이후 `업로드 확인`에서 학년도·학년·반·이름·같은 임시암호로 기록을 조회합니다.

초기 제한은 파일당 8 MB, 접수당 24 MB, 최대 10개입니다. ZIP은 원본 합계 20 MB, 최대 40개입니다. 이는 프로그램 운영 기본값이며 Google의 공식 업로드 한도를 뜻하지 않습니다. 운영 설정에서 바꿀 수 있으나 큰 파일에서는 브라우저 메모리와 Apps Script 실행 제한의 영향을 받습니다.

학생 검증은 현재 학년도 유효 학생이 전체 70명 이상이면 전체 적용하고, 70명 미만이어도 해당 학급 15명 이상이면 그 반에 적용합니다. 그 외에는 명렬표 대조 없이 업로드합니다. 학생 정보 일치는 보호자 본인 인증이 아닙니다.

## 13. 파일·삭제·보안 동작

- 실제 파일은 학교 제출자료/학년도/제출함/학생 폴더 아래에 저장됩니다.
- 학생 ID가 있으면 동명이인 혼합을 막기 위해 학생 폴더 끝에 짧은 ID가 붙습니다.
- 파일은 원본이름[날짜-시각].확장자 형식으로 저장됩니다.
- 다운로드는 서버 권한 검사 후 파일 내용을 전달합니다. 링크 공개 공유를 만들지 않습니다.
- ZIP은 메모리에서 생성해 전달하므로 별도의 공유 ZIP 파일을 남기지 않습니다.
- HWP/HWPX·XLS/XLSX·PDF·지정 이미지 형식을 지원합니다. 모든 그림 형식을 무제한 지원하는 것은 아닙니다.
- 일부 형식은 헤더를 추가 확인하지만 완전한 악성 코드 검사를 제공하지 않습니다.
- 임시암호는 접수별 솔트와 서버 비밀값으로 HMAC 검증값만 저장합니다. 복호화 가능한 암호화가 아닙니다.
- 임시암호는 복구할 수 없습니다. 암호를 잊은 경우 담당 교사에게 확인해야 합니다.
- 조회 시도 제한은 CacheService 기반의 간단한 완화 장치입니다. 완전한 봇 차단·DDoS 방어가 아닙니다. 익명 대량 업로드에 노출되는 대규모 공개 서비스용 구조는 아닙니다.
- 교사 화면에 전화번호와 임시암호를 보내지 않습니다.
- 프로젝트 편집자와 DB 소유자는 개인정보 원본에 접근할 수 있으므로 편집자를 최소화하세요.

제출함 삭제 예약은 비활성화 후 30일이 지나면 폴더를 휴지통으로 이동합니다. 유예 기간에는 앱에서 복원할 수 있습니다. 휴지통 이동 후에는 드라이브 소유자가 직접 복원해야 하며 앱 목록의 자동 복구는 지원하지 않습니다. 파일 개별 삭제도 휴지통 이동입니다. 영구 삭제·Vault 보존 해제는 구현하지 않습니다.

`자료 보관 검토 기준`은 운영 참고값입니다. 날짜가 지났다는 이유로 자동 파기하지 않습니다. 학교 보관 정책에 따라 관리자가 제출함 삭제를 예약하세요. 접수 메타데이터·감사 로그·CSV 백업은 별도로 관리·파기해야 하며, 제출함 폴더 휴지통 이동만으로 모든 개인정보가 삭제되는 것은 아닙니다.

## 14. 코드 수정 후 배포에 반영하기

1. 수정된 파일을 부분적으로 섞지 말고 해당 파일의 전체 코드로 교체합니다.
2. 저장합니다.
3. `배포 → 배포 관리`를 엽니다.
4. 공개용 배포를 선택하고 연필 버튼을 누릅니다.
5. 버전을 `새 버전`으로 선택하고 배포합니다.
6. 교직원용 배포도 같은 새 코드 버전으로 업데이트합니다.

기존 배포를 편집하면 URL을 유지할 수 있습니다. 새 배포를 따로 만들었다면 운영 설정의 URL도 바꾸세요. 두 배포는 실행 주체가 모두 배포자이고 접근 대상만 다릅니다. 학생·학부모에게 DB나 전체 드라이브 폴더를 공유하지 마세요.

## 15. 어려울 때 확인할 항목

| 증상 | 확인 |
|---|---|
| 초기설정 실행이 막힘 | 설정.gs 이메일과 현재 편집기 계정 일치 여부 |
| 로그인 후에도 로그인 안내 반복 | B가 학교 제한 배포인지, 같은 조직 계정인지, 이메일 식별 가능한 환경인지 확인 |
| 로그인 버튼 없음 | 운영 설정의 두 배포 주소 등록 |
| 학년·반이 없음 | 현재 학년도 학급을 먼저 생성 |
| 학생 CSV 반영 실패 | UTF-8 또는 한글 Windows 인코딩, 학급·번호·열 제목 확인 |
| 교사가 제출함을 못 봄 | 승인 상태·선택 학년도·제출함 권한 확인 |
| ZIP 실패 | 파일 수·원본 합계 크기를 줄여 선택 다운로드 |
| 화면에 수정이 안 보임 | 두 배포 모두 새 버전으로 업데이트했는지 확인 |
| 정기 정리 오류 | 편집기 왼쪽 실행 메뉴와 관리자 감사 기록 확인 |

첫 자료 등록 시 1학년 1반처럼 작은 범위부터 입력하면 설정을 이해하기 쉽습니다. 코드 수정은 원본을 별도로 보관한 뒤 파일 전체를 교체하세요.

## 16. 이번 제공 범위의 제한

- 실제 학교 계정에서 배포·동작 확인하지 않은 소스입니다.
- 대용량 스트리밍 업로드·브라우저 종료 후 업로드 이어받기는 제공하지 않습니다. 같은 화면에서 실패 파일 재시도와 저장 상태 조회를 제공합니다.
- 파일 내용 미리보기 없이 목록·다운로드를 제공합니다.
- 사용자 로그인 세션은 Google이 관리합니다. 앱 자체 계정 비밀번호나 별도 OAuth 서버를 만들지 않습니다.
- 초기 관리자 목록은 Script Properties의 ADMINS에서 관리합니다. 여러 명이면 쉼표로 구분하되 같은 학교 도메인 계정만 사용하세요.
- 학급 제출함·폴더 생성 중 서비스 오류가 발생하면 재실행으로 기존 자료를 재사용할 수 있지만, Drive와 Sheets 사이에 완전한 트랜잭션은 없습니다. 실패한 초기 생성 폴더 등은 소유자가 확인해 정리해야 합니다.
- 스프레드시트는 내부 목록을 일괄 읽고 화면은 페이지 단위로 표시합니다. 데이터베이스 서버처럼 행 인덱스로 조회하는 구조가 아니므로 대규모 장기 누적 데이터에서는 학년도별 프로젝트·DB 분리 등 운영 조정이 필요합니다.
- 정기 통계는 매일 갱신되고 대시보드는 현재 기록을 기준으로 계산합니다. 자료가 적은 학교 단위 이용을 목표로 합니다.
